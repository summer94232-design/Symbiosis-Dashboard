# 精確 TWR 與整組 Google 重複規則

版本：`v26.9.10.2`。本次僅修改本機程式及隔離測試，未部署、未修改正式帳務、歷史快照或 Google 行程。

## 精確 TWR 的使用方式

在「資產趨勢 → 精確 TWR」填寫期初／期末日終淨值及估值依據，再補齊區間內每筆出入金的台北時間、流量前帳戶淨值及依據。相同秒數內的多筆流量使用明確的先後順序，不能用日淨流量互抵。

淨值包含全部持倉市值及帳戶現金，扣除融資負債；股利、買賣收付留在帳戶內，只有外部出入金作為切段點。若有未登錄的外部資產轉入／轉出，必須先補齊正確的帳務資料，不能由計算程式推測。

每段報酬因子為「本段流量前淨值 ÷ 上段流量後淨值」。流量後淨值等於流量前淨值加上有正負號的出入金，假設資金移轉瞬間沒有市場變動。最後一段以期末淨值結束，所有因子連乘後減一，顯示未年化的區間報酬及子期間明細。

範例：期初 100、入金前淨值 110、入金 100、期末 220，TWR 為 `(110 / 100) × (220 / 210) − 1 = 15.238095…%`，不是將入金當成期末流量得到的 20%。

### 資料與安全界線

- 日期採日終端點，流量範圍為 `(起日, 迄日]`；今天尚未結束，因此期末必須早於今天。
- 沒有當時估值，不會拿今日報價、成本或每日快照代替。精確公式已實作，但估值品質及帳務完整性仍由實際資料決定。
- 缺估值、缺依據、無效資料、負淨值、流量使帳戶歸零或跨越重新入金時不提供可延續的報酬；沒有外部流量且期末全損可呈現 −100%。
- 原有相鄰快照圖表繼續標示「近似 TWR」；本次新增獨立的精確區間計算與分段明細，並未把舊曲線改名為精確。
- 確認後保存於 `users/{uid}/settings/exactTwr`，目前保存最近一組區間。原有 JSON 備份已涵蓋 settings，故估值與依據會一併備份還原；不改写歷史快照。
- 出入金、交易或股利資料變更後，帳本指紋不符，取消舊精確結果的確認狀態。讀取失敗或斷線不显示尚未確認的結果。跨集合讀取不是整本帳務的伺服器原子快照，保存後若有其他裝置持續變更，須待同步並重新核對。
- 固定帳號、保存前重新讀取帳本、Firestore transaction 比對估值版本；另一裝置的估值不會被舊表單蓋掉。相同內容重送可安全完成。

## 編輯整組重複規則

在月曆選取已同步的 Google 重複行程，開啟編輯後選「編輯整組重複規則」。此入口會另外讀取系列主事件，不以某次發生的事件當成整組。

- 簡易模式：每日／每週／每月／每年、間隔、每週星期、系列總次數或持續重複。總次數包括已發生次數；每月及每年沿用原始起始日期。
- 進階模式：完整編輯 RRULE、RDATE、EXDATE，包括 UNTIL 截止日期及例外日期。無法無損轉成簡易表單的規則保留進階模式，不刪除未知欄位。具體規則合法性仍由 Google API 驗證。
- 保存前先呈現影響整個系列的確認畫面，再套用。只 PATCH 主事件的 recurrence，保留原始起始時間、時區、標題及其他欄位；不是「只改這次」或「這次以後」，也不是逐次 PATCH。
- 使用讀取時的 ETag 及 If-Match；Google 端有並發修改時拒絕覆寫。回覆遺失後若同樣的規則已套用，可安全重試。
- 保存後逐筆 GET 既有連結的事件，只有明確取消／404／410 才清除本機副本，並以 transaction 確認本機未變更。讀取失敗或有未同步的本機修改時保留資料、提供重試。
- 再經既有同步匯入新產生的次數，仍採既有前後半年窗口，不下載無限歷史或未來。Google 規則已保存但本機刷新失敗時，明確提示並提供「刷新整組行程」。單次例外沿用 Google 的系列處理行為，未另做展開覆寫。

## 部署設定

新增 `google-calendar-series` Netlify Function，僅支援 POST，使用同一 Firebase ID token、允許 UID 及共享用量限制。須先完成上一批的 `API_FIREBASE_PROJECT_ID`、`API_FIREBASE_SERVICE_ACCOUNT`、`API_ALLOWED_UIDS`，並沿用 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET` 與使用者既有 Google 連結。

系列操作額度：每使用者每分鐘 30、每天 300；全域每天 1000。一次檢查最多 50 個既有次數、上游並發 4 個；單個請求 10 秒逾時，共用 Google 操作時間上限 24 秒。失敗不自動重送計費請求。

Google refresh token 的現有保存方式未改動（F17 仍暫緩）；F16、Fugle／Gemini 金鑰後端化、附件實體備份還原及既有歷史帳務核對也未列入本次。

## 驗證

- 321 項一般回歸測試通過，新增 19 項涵蓋精確公式、多筆同日流量、同秒排序、缺值／零淨值、規則保留、ETag 衝突、重試、確認取消及切帳號。
- 12 項 Firestore／Storage Emulator 測試通過，新增真實估值 transaction 的並發、重送及跨帳號拒絕；備份往返加入精確 TWR 估值紀錄。
- 隔離瀏覽器：確認 15.2381% 與明細、帳本變更後取消確認、整組頻率與次數修改、畫面內確認、保存及刷新。原生日期／時間欄位以鍵盤觸發驗收。
- 所有瀏覽器測試使用記憶體資料與阻擋外連的 fixture；不代表真實 Google、已部署 API 或正式估值已驗收。
- lint 零錯誤／警告、正式建置通過；仍有既有大型套件提示。實際系列 Function 模組可載入，匿名 POST 會回覆 401。

計算與同步依據：[GIPS 手冊的真實 TWR 分段與幾何連結](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/)、[Google 重複事件](https://developers.google.com/workspace/calendar/api/guides/recurringevents)、[Google ETag 版本控制](https://developers.google.com/calendar/api/guides/version-resources)。
