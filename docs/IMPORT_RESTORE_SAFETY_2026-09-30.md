# CSV 匯入與備份還原保護（2026-09-30）

顯示版本：`v26.9.30.2`。此批沿用現有 Firebase／Netlify 架構，沒有新增服務或部署。

## 變更

- 交易頁 CSV 匯入在讀檔前固定兩個 Firebase 的登入 session；讀檔、查詢、每筆寫入及股票名稱更新後都確認帳號未變。切換帳號會中止剩餘操作，已完成資料留在原帳號。
- 匯入失敗會結束 loading、清空檔案輸入並回報已完成筆數。帳號變更後不會由舊頁面重新載入新帳號資料。
- JSON 還原在第一批寫入前驗證整份交易、出入金、股利與快照，阻擋無效日期／數字、重複帳務文件 ID、收付與資產拆分不一致。
- 有交易或股利時，從伺服器讀取現有帳本，依原本「同 ID 覆蓋、其餘保留」規則計算還原結果，阻擋新增或加重超賣及新增失效當沖配對。
- 舊交易省略費稅時，依既有計算的零元預設驗證；不回寫預設值，不重算或改寫備份內的歷史金額／日期。保留合法先賣後買待回補紀錄與負現金快照。
- 還原前檢查失敗的提示明確說明尚未寫入資料，並顯示資料類別、筆數或文件 ID 與錯誤原因。

## 驗證

新增實際匯入／還原函式的回歸測試，遠端 I/O 使用記憶體資料替代，包含帳號切換、寫入後字典失敗、晚於第 400 筆的錯誤、合併帳本超賣、配股改期、配對失效及合法舊資料還原。測試納入 `npm test`。

## 保護邊界

帳本驗證是寫入前的伺服器資料預檢，沒有鎖定其他裝置；大型還原仍按批次、跨兩個 Firebase 專案寫入。中途網路或權限失敗可能留下已完成批次，需確認原帳號資料後重試。此批沒有改造跨裝置原子交易，也沒有讀取或修復正式歷史資料。

Firebase emulator 本機 Java 無法啟動；未宣稱本批完成 emulator 驗證。沒有更動正式安全規則。
