# 元大月結核對修正 v26.9.12.2

使用原始 PDF 與完整備份在本機重現對帳流程。實際帳戶金額、證券紀錄與修正草案存放於已排除版本控制的 `output/reconciliation/`；原始檔與雲端資料未修改。

## 修正

- 元大月報的買沖／賣沖也屬於成交列；保留券商當沖標記，不改寫使用者既有配對。
- 以 PDF 印出的成交金額、費用、交易稅與淨收付合計驗證解析完整性，避免解析器與筆數偵測一起漏列。
- 正式月結核對顯示一元與角分差異；月中 OCR 保留原有容差。融資償還一致仍須核對實際淨收付。
- 零稅額賣出不把 PDF 頁碼誤當金額；處理金額正負號。
- 出借剩餘股數以出借市值交叉驗證後才合併至總持股，已還券原始數量不重複加入。
- CMA 解析辨識出借收入、存款利息、外部入金、預繳、退款、再投入等摘要，出借頁應計收入不當成 CMA 已收現金。
- 月底持股與現金採 `asOf` 日期與實際股利發放日，避免把跨月股利提前計入。
- 股利配對尊重明確入帳日期，舊資料只在同股、前 90 天候選中比對；這種候選配對仍需依實際發放文件確認。
- 不完整 PDF、多份月報混合或改動原始期間不能保存成正式單月核對結果。
- 修正乘法浮點噪音導致整數成交額被少算一元的情況，真正的角分仍按既有規則捨去。

## 本機工具

`npm run audit:broker -- <備份.json> <輸出資料夾> <月結.pdf> ...`

逐份 PDF 核對、輸出 `audit.json` 與 `audit.md`，並記錄來源 SHA-256。使用和網頁相同的 PDF.js 文字順序、計算與對帳函式；不需要登入、不連接 Firebase。掃描或加密 PDF 不在這支 CLI 的支援範圍，瀏覽器仍保留原有 OCR 與密碼功能。

## 驗證範圍與限制

新增 `tests/broker-statement-audit.test.mjs`，涵蓋當沖漏列、列印合計、出借／還券、零稅頁尾、浮點取整、正式與 OCR 容差、融資淨收付、跨月交割、股利配對及唯讀備份檢查。

對帳單只能驗證其列示月份的交易、月底參考價、CMA 與庫存；不能推定其他日子的收盤淨值。原始快照、權利紀錄與投入本金不會被此批程式自動改寫。出借／CMA 利息仍需要獨立收益記帳模型，不能用外部入金代替。歷史帳差需要前期來源證明後才能修正，不能再次補一筆金額讓餘額歸零。

部署依 AGENTS.md 等待使用者對本批明確批准。
