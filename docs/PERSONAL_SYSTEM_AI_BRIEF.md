使用方式：填寫下方需求，再將整份內容貼給能協助寫程式的 AI。這份指令可單獨使用；若要更多功能選項，也可一併附上《個人整合管理系統建置企畫書》。

## 我想參考的系統方向

參考 Symbiosis 的三大模組，按我的需求取捨：

1. 知識管理：文字／網址筆記、標籤、搜尋、模板、圖片／文件、筆記連結、垃圾桶、匯出；進階可做 AI 分類和知識圖譜。
2. 行事曆與任務：月曆、事件、待辦、優先級、截止日、專案、今日總覽；進階可做 Google Calendar 同步。
3. 投資管理：交易、持倉、出入金、股利、自選股；進階可做資產趨勢、年度復盤、對帳、融資、組合試算、觀點與產業圖。

不預設需要所有模組。第一版通常是：登入、總覽、筆記、標籤、任務、月曆、垃圾桶、設定、JSON 備份及還原預覽。

## 預設技術方向

前端使用 React + TypeScript + Vite；登入與資料庫使用單一 Firebase 專案的 Authentication、Cloud Firestore；前端網站預計部署 Netlify；有 AI 或其他外部 API 時使用 Netlify Functions 作為後端代理。Git 與 GitHub 私人儲存庫保存程式版本。

圖片／文件使用 Cloud Storage for Firebase 是選配。請查核當時官方計費條件：目前需要 Blaze 方案，不能承諾免費；如果我不願意綁計費，先完成文字版本。

使用 AI 幫我寫系統，不代表第一版需要內建 AI API。需要內建時先選一個供應商，保管後端 API key，並做登入驗證、用量限制與錯誤提示。

請查核當時套件相容性並固定版本，保留 lockfile，不必一次加入所有圖表、OCR、編輯器或資料服務。

## 先交付設計，再做可運作的本機版本

請先交付以下內容：

1. 我的使用情境與第一版範圍。
2. 功能優先順序、導覽和主要頁面的配置。
3. 資料結構、關聯、權限和刪除規則。
4. 我需要準備的帳號、設定、費用條件與本人操作步驟。
5. 分階段工作清單與每階段驗收方式。

如果我已提供可操作的專案且授權開發，接著直接完成第一版的本機實作，逐步交付，不要只留一份建議。缺少雲端帳號時，先建立可運作且明確標示的模擬資料模式；沒有完成的外部連線請誠實列為待設定。

## 開發要求

- 繁體中文介面，手機優先；縮小多餘留白、內距和列高，但保留可讀文字、重要資訊與好點擊的操作。檢查手機直向、橫向和電腦。
- 資料依 UID 隔離；未登入不得讀寫私人資料。Firestore、Storage 和後端端點都要驗證權限。
- 不自行保存明文或可逆密碼，不把 AI API key、服務帳號憑證或 OAuth secret 放到前端、Git 或一般備份。Firebase 前端公開設定與真正秘密金鑰要分清楚。
- 登出清除私人快取，匯入／還原過程綁定開始操作的帳號。
- 筆記以穩定 ID 關聯，列表分頁，正文按需載入；搜尋要明確標示範圍，全文搜尋需另外設計。
- 日期、全天事件和定時事件明確區分，正確處理時區。
- 一般刪除先進垃圾桶；永久刪除和連帶刪除先顯示影響範圍。
- JSON 備份保存資料 ID、原始欄位和格式版本；還原前顯示差異，再由我確認。定義合併或取代行為，說明部分成功和重試方式。
- 附件引用不等於檔案備份；如支援附件，另規劃實體檔案的匯出與復原。備份排除秘密憑證。
- 載入、空資料、錯誤、離線與重試都有明確狀態；寫入確認成功才顯示已儲存。
- Google 同步先做手動單向，再做雙向；雙向需定義衝突、刪除範圍、防重複與部分失敗處理。
- AI 功能由我手動觸發，只傳必要資料，建議經我確認才寫入。
- 投資功能如啟用，先服務我的單一券商；行情來源不等於交易帳戶整合，不做自動下單。資金流採實際日期，報價標示來源和時間；近似與精確績效需區分。試算與真實帳本隔離。

## 驗證與交付

每個階段提供實際檔案、安裝與啟動指令、操作說明、驗證結果和待完成項目。

驗證至少涵蓋：資料新增後重整仍保留、任務與月曆日期正確、未授權存取被拒絕、垃圾桶復原、測試環境備份還原，以及手機主要流程。選配功能只驗證已啟用的部分。

先做與變更相關的驗證；登入、權限或共用資料結構變動時擴大測試。不用未執行的檢查宣稱通過。

請在專案留下 README、環境變數範例、資料結構、測試與發布方式，以及 AI 開發規則。不要將我的私人資料或參考系統的帳號、金鑰放進範例。

正式 Netlify／Firebase 部署、正式權限規則和正式設定修改，請先完成本機成果與驗證，再列出本次批次發布清單，等待我明確批准。先前批准不適用後來的新批次；設定 Git 自動發布時也需遵守這個流程。
