# F10、F18、F08、F15、F20 修正紀錄（2026-09-08）

## F10：未操作正文也可保存

noteBody 在 contentDoc 未定義時省略欄位，保留原純文字與附件資料；不使用空富文字文件覆蓋舊正文。標題、網址收藏及舊筆記只改標題的資料，已使用實際 Firebase SDK writeBatch.set 驗證序列化（未 commit、未送網路）。

## F18：保留 Google 事件的時間語意

目前只同步單日全天且非重複的事件。Pull 保留 start、end 與 recurringEventId；時段、跨日及重複事件標示 unsupported，前端略過其新增、更新、刪除及反向推送，並顯示提示。

新建本機副本後回填 sourceId 改為明確 linkOnly，只 PATCH extendedProperties。一般更新與刪除前先重新 GET Google 事件；不支援的事件保留，使用 If-Match ETag 防止覆寫同步期間的新版本。

Google 官方依據：[Extended properties](https://developers.google.com/workspace/calendar/api/guides/extended-properties)、[Events resource](https://developers.google.com/workspace/calendar/api/v3/reference/events)。未對真實 Google 行事曆執行同步；以 API fixture 驗證請求欄位。

## F08：標籤統計不再依事件重複累加

移除 before／after 增減方式。每次觸發以 transaction 讀取該帳號當前所有筆記摘要及統計，重算去重後的標籤數、根標籤数、未分類與總筆數；只有值變動時才寫入統計。索引亦從交易內的當前筆記生成，不以過時事件回寫舊標籤。開啟重試，重送、亂序與 metadata 自觸發不會重複計數。

取捨：這是全摘要重算，單次讀取成本隨筆記數增加。部署後有新筆記事件時會校正該帳號統計，但本次未主動重建正式統計；大量筆記日後可改為具版本的單筆貢獻模型。

## F15：連結與刪除／復原一致性

新增 kmsNoteLinks 共用交易。連結定義為有效筆記之間的雙向關係：

- 從資料庫讀取原筆記與關聯筆記，補查舊版非對稱的 incoming links，不依賴畫面篩選。
- 保存摘要、正文及反向連結一起提交。updatedAt 與 graphRevision 檢查阻止舊表單覆蓋較新修改。
- 刪除時清理現存反向連結並保留垃圾桶的關係記錄；兩則關聯筆記均刪除時，從垃圾桶查詢反向關係，讓不同復原順序仍可重新連結。
- 復原只連到當下仍存在的筆記；另一則稍後復原時再接回，不製造指向不存在筆記的連結。
- 已復原、關聯失效、超過 449 個關聯或切帳號時中止。圖片與正文沿用原 ID，不在此交易刪除。
- 首次載入完整輕量摘要，提供跨標籤連結候選；編輯前重新讀取當前摘要與正文。

未全量修復既有非對稱連結；本次保護保存／刪除／復原路徑。其他管理工具、多筆標籤操作與 Storage 永久清理的並發仍須另外驗證。

## F20：搜尋範圍與實際結果一致

搜尋明確限定為標題、標籤、網址（不含正文），不是新增全文搜尋。文字候選改掃描筆記摘要，不再使用會截斷的 300 個 searchTerms；最終比對共用 NFKC、大小寫與空白正規化。長標題尾端、標籤、URL 均不會在索引候選階段漏掉。舊搜尋回應失效後不覆蓋新查詢。

取捨：文字搜尋每次讀取全部摘要，未讀取全部正文；筆記規模增大時應評估專用搜尋服務與分頁。
