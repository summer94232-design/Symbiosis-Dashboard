# AI 助理偏好確認清單

整理日期：2026-10-02（Asia/Taipei）

這份文件是功能規格草案，用來確認需求與找出遺漏。本次只建立文件，尚未實作 AI 助理、變更應用程式版本或部署。

標記說明：

- **已表達**：使用者在討論中明確提到的需求或重點。
- **建議預設**：助理提出的做法，仍可調整，不能視為使用者已同意全部細節。
- **待決定**：實作前需要釐清的偏好或限制。

## 二、目前的建議預設，請確認是否符合你的習慣

| 編號 | 狀態 | 建議做法 |
| --- | --- | --- |
| R1 | 建議預設 | 電腦可開啟右下方浮動聊天視窗；手機使用接近全螢幕的面板。可縮小、關閉收起或放大。 |
| R2 | 建議預設 | 全系統共用同一段目前對話；切換投資、知識庫或行事曆頁面不重新建立聊天。若提供完整對話頁，它與彈窗共用狀態。 |
| R3 | 建議預設 | 收起彈窗保留目前對話；重新整理可由本機恢復；按「新對話」或「結束對話」才清除目前內容。登入帳號之間不混用對話或偏好。 |
| R4 | 建議預設 | 目前對話只在本機暫存，不建立舊對話列表，不逐句寫入雲端。長期偏好保存在少量雲端資料中，變更時才同步。 |
| R5 | 建議預設 | 不強迫先選股票／生活模式，不固定每次回答的段落與格式。引用、時間判讀與推論可辨識，是基本品質要求。 |
| R6 | 建議預設 | 日期與事件按相關段落判讀。同一篇筆記可包含不同時程，不因整篇建立日期而全部排除或全部認定有效。 |
| R7 | 建議預設 | 「明年」「未來三年」等說法需要可信的來源時間才能換算；收藏／編輯時間不等同原始資料時間。沒有依據時保留原文並標示不明。 |
| R8 | 建議預設 | 舊資料可用於背景、比較與發想。列為當前投資研究候選時，需要交代題材時程、現況證據、反對證據及尚未確認之處；未來時程本身不能證明題材仍成立。 |
| R9 | 建議預設 | 重用搜尋索引與已讀資料，按問題取回相關正文。第一次使用或資料更新仍可能有讀取，不承諾零用量。 |
| R10 | 建議預設 | 只讀取少量資料時顯示分析範圍，不聲稱已看完全部知識庫；可繼續擴大研究範圍。 |
| R11 | 建議預設 | AI 視窗按需載入；開啟視窗不自動分析全庫。聊天內容更新與原頁面圖表、表格分開，避免不必要的重畫。 |
| R12 | 建議預設 | 第一版以查詢、討論、整理及產生草稿為主。保存結論或修改現有筆記由明確的使用操作觸發；不自動更改投資帳務資料。 |

## 三、需要你決定的偏好

這些項目可以分批回答；沒有答案的項目保持待定，不視為默認同意。

| 編號 | 要決定的地方 | 可選方向／建議 |
| --- | --- | --- |
| P1 | AI 能讀哪些資料？ | 建議可查知識庫與投資研究；持倉、成交紀錄、資金金額只在問題相關時使用。確認是否有私密筆記或標籤要排除。 |
| P2 | 用哪家 API、哪些模型？ | 可先沿用既有 Gemini，或另選供應商。是否需要手動切換模型？建議有預設模型；更換模型後保留目前對話與偏好，但不保證回答完全相同。模型能力、價格與資料處理方案需一起評估。 |
| P3 | 費用與每日用量上限？ | 填寫可接受的每月 AI 費用，以及 AI 請求、網路搜尋與資料庫讀寫的預算。資料庫還需要保留原功能用量。實際計量不一定等於按鈕點擊次數。 |
| P4 | 什麼時候聯網查證？ | 可選「需要現況時自動查」「只在我按查證時查」「預設關閉」。建議按問題需要、在上限內查證；沒有查證時不能把舊筆記標成已確認的現況。 |
| P5 | 平常回答風格？ | 偏精簡或偏深入；先給結論或先討論；是否主動挑戰你的看法。建議自然對話，依問題調整，可以指出矛盾，不固定格式。 |
| P6 | 長期偏好如何更新？ | 可選「只記我明確要求的內容」或「也從反覆互動提出偏好候選」。建議明確要求可記住；推測的習慣先作候選，能檢視、修改、移除，不讓一次性要求變成永久習慣。 |
| P7 | 長期記憶要包含什麼？ | 除回答風格與使用習慣，是否也記目前研究的主題、未解決的問題？建議穩定偏好與有日期的研究狀態分開；舊投資看法不當成永久事實。 |
| P8 | 目前對話要保留到何時、在哪些裝置？ | 可選只在本機保存，或跨裝置接續。建議第一版目前對話只存本機、長期偏好跨裝置同步；目前對話直到你結束或開新對話才清除。長對話可用摘要接續，必要時查回原段落。 |
| P9 | 目前頁面的內容要如何帶入？ | 可選自動使用正在看的筆記／持倉資訊，或按「帶入目前內容」。建議明確帶入有成本或私密的內容；仍允許依問題搜尋其他相關筆記，不只限制在當前頁面。 |
| P10 | 圖片、PDF 與其他附件要支援到哪裡？ | 可選第一版只分析文字，或按需讀圖片、PDF／文件。建議先做好文字與來源引用；附件解析、圖表、掃描辨識另外顯示用量與限制。網址收藏不代表正文已收錄。 |
| P11 | 投資協助的深度？ | 可選只整理研究候選，或進一步討論估值、進出場條件、反對情境。建議先以可核對的研究與討論為主；涉及現價、財報等時效資料，要標示截至時間。仍只使用元大證券帳戶範圍。 |
| P12 | 結論要怎麼帶回系統？ | 可選只顯示／複製，或加「存成新筆記」「新增追蹤任務」。建議複製與存成新筆記可選；修改原筆記先看草稿，不自動改帳務。這與不保存舊聊天紀錄是不同的選擇。 |
| P13 | 額度不足、API 失敗時怎麼辦？ | 可選停下並保留草稿、手動重試，或在你授權的模型範圍內切換。建議保留對話、不反覆自動重試，也不默默切到較昂貴模型。停止生成可以停止等待，但不保證已開始的供應商用量退款或取消。 |

## 四、容易遺漏的差別

1. **偏好記憶與研究結論不同。** 可以記得你如何喜歡討論，不應把你曾經看好的產業當成永久正確答案。
2. **時間未知不等於整篇筆記無用。** 仍可整理與發想，但現況判斷要說明未知或補查證據。
3. **題材仍成立與價格有吸引力不同。** 若討論買賣條件，需要另看相關價格、估值、財報與風險資料；不能把未來發展時程直接當成買入結論。
4. **本機沒有歷史列表，不代表 API 供應商沒有資料保存。** 選模型時要確認免費／付費方案的資料用途與保存政策。Google 對 Gemini 未付費與付費服務的資料用途有不同規定；付費服務也有特定情況的資料保存，不代表完全零保留。[Gemini API 條款](https://ai.google.dev/gemini-api/terms)
5. **省資料庫讀取，不代表 AI 費用也歸零。** 輸入文字量、回答長度、模型、附件與聯網工具都有各自用量；長對話不每次重送完整歷史。
6. **完整資料覆蓋需要成本。** 若問「所有筆記有哪些共同趨勢」，要分批分析並說明已覆蓋範圍，不能只取少量資料卻宣稱全庫結論。
7. **來源引用也需要驗證。** 引用應能對應真正讀過的原文或工具返回來源；提示詞與輸出格式本身不能保證內容正確。搜尋結果的保存與重用也要符合選定工具的資料處理規則。

## 五、實作時必須驗證的項目

以下是工程要求，無須使用者在多種不安全選項間做選擇：

- API 金鑰由後端保存；資料讀取使用登入帳號權限，偏好與對話不可跨帳號混用。
- 更換帳號、登出與新對話後，舊請求不應回寫到新的對話；較晚回來的回答不覆蓋較新的狀態。
- 長期偏好可查看、修改、刪除；明確指令優先於推測偏好。
- 開關視窗、換頁與放大縮小不重複送 AI 請求；原頁面輸入與位置保留。
- 網路失敗與額度不足不遺失目前對話，不以無限重試或無聲升級模型增加費用。
- 保留原有淺色／深色與藍紫主色；手機介面緊湊。驗證電腦、窄手機、直向、橫向與鍵盤出現時的布局。
- 分別測量首次開啟、長對話、資料檢索、附件解析與生成期間的效能，不能在測量前保證沒有影響。
- 依專案規定，實作與本地驗證完成後，部署仍需本批次的明確批准。

## 六、回覆方式

可以直接指出要調整的編號，例如：

> R3 保留；P4 我希望需要現況時自動查；P6 可以從互動提出偏好候選；P8 目前對話只存本機；P3 每月預算是……。

沒有回覆的待定項目保持待定。這份清單的目的是確認完整範圍，不要求一次回答全部項目。

## 七、選項版

每題 A 是建議起點，不代表已獲同意。可選單一項，也可說明 A／B 皆可等接受範圍；若選項組合衝突，需整理清楚後才能成為實作規格。

| 題號與項目 | A：建議起點 | B | C |
| --- | --- | --- | --- |
| P1 資料範圍 | 知識庫＋投資資料，依問題需要讀取 | 只讀知識庫，不讀投資帳戶資料 | 知識庫＋投資研究，但排除實際持倉數量、成交及資金金額 |
| P2 模型選擇 | 先沿用 Gemini，保留手動切換模型 | Gemini 固定一個模型 | 可使用其他／多家 API，手動選擇模型 |
| P3 每月 AI 預算 | NT$100 以內，作為費用控制目標 | 只用免費額度，不自動付費 | NT$300 以內，作為費用控制目標 |
| P4 聯網查證 | 需要現況時在額度內自動查 | 按「查證」才查 | 預設只用筆記，需要時另行開啟聯網 |
| P5 回答風格 | 先清楚回答，依問題深入，可主動指出矛盾 | 預設深入分析，積極提出反對觀點 | 先短答，再以追問逐步討論 |
| P6 偏好更新 | 明確偏好直接記住；推測偏好列候選 | 只記我明確說「記住」的內容 | 可從反覆互動自動更新偏好，但能檢視、修改、刪除 |
| P7 長期記憶範圍 | 穩定的互動偏好與使用習慣 | 加上有日期的研究主題與未解決問題 | 再加上我明確指定的背景與限制 |
| P8 目前對話保存 | 只存本機，換頁與重新整理可恢復；長期偏好跨裝置同步 | 目前對話和偏好都可跨裝置接續，結束後不留聊天歷史 | 目前對話不跨重新整理／關閉分頁保存；長期偏好跨裝置同步 |
| P9 目前畫面帶入 | 依問題自動使用相關的目前頁面與筆記內容 | 按「帶入目前內容」才使用頁面內容，仍可依問題查筆記 | 不自動帶入頁面，只依問題檢索已允許的資料 |
| P10 附件 | 第一版先支援文字筆記 | 加上文字型 PDF／文件 | 也支援圖片、掃描 PDF 與圖表，解析失敗需明示 |
| P11 投資討論深度 | 研究方向、支持／反對證據，也可討論估值與進出場條件 | 只整理研究候選與證據 | 再加上持倉配置、集中風險與情境試算 |
| P12 結論處理 | 可複製或手動存成新筆記 | 只顯示與複製 | 再加上建立追蹤任務、產生修改原筆記的草稿 |
| P13 失敗處理 | 保留對話，讓我手動重試 | 適合重試的暫時錯誤，額度內最多自動重試一次 | 可在已允許且預算內的模型之間切換，顯示原因 |
| P14 資料隱私 | 選擇輸入不作產品／模型改進用途的 API 方案；接受條款規定的有限保存 | 可使用免費方案，但只傳你指定可公開的資料，私密內容排除 | 私密內容先遮蔽／改寫，再送外部 API；無法可靠處理時不送出 |
| P15 資料庫額度分配 | 給 AI 不超過每日讀取、寫入額度各 10% 的目標預算，優先保留原功能用量 | 更保守：各 5% | 可到各 20%，但仍優先保留原功能用量 |

補充：

- P3 可直接改成其他金額或區間。API 方案、模型、工具與實際計量方式確定後，才能核算實現方式；費用控制不能只靠前端按鈕計數，也不能當成供應商零誤差帳單保證。
- P14 的三種做法仍需確認選定供應商條款與資料種類。遮蔽不保證完全匿名，也不能因此把供應商禁止提交的內容直接送出。
- P15 是分配政策，尚未有精確可用額度。需先確認兩個資料庫的實際額度與原功能用量，再換算各自讀取／寫入上限；統計要包含後端、索引及其他衍生操作，不能把一次問題或一次批次當成一筆讀寫。
- P8 的 C 在重新整理、關閉分頁或登出後開始新的對話；無論選哪一項，單純切換系統頁面都保留目前對話。
- P5 是初始風格，仍可在每次對話中改變，不強制固定段落模板。
- P11 全部是分析討論，不包含代為下單或自動修改帳務；時效資訊仍須標示來源與截至時間。

回覆範例：`P1A、P2A、P3 每月 100～200 元、P4A/B 都能接受、P6A、P8A、P14A、P15B`。

| P8 | A | 目前對話只存本機，換頁與重新整理可恢復；長期偏好跨裝置同步。無舊聊天列表；結束或新對話清除目前內容。 |
| P9 | A | 按問題需要自動使用相關的目前畫面與筆記內容，不自動將整個知識庫或整個帳戶資料全部送出。 |

| P15 | C | AI 的目標預算最多占每日讀取、寫入額度各 20%，且優先保留原功能用量；兩個資料庫的實際額度、方案與原功能使用量尚需確認。 |

已延續的規則：投資資訊按段落及事件時程判讀，不強制手動日期欄位；模糊時間標示不明；舊資料保留研究價值，但不能無證據宣稱目前有效。保持原有配色、緊湊的手機布局與原頁面操作狀態。

接續需要補充的資料：

1. 供應商與第一版模型已確認，詳見 P2 與第十節。後續仍需確認各供應商帳戶的實際模型存取權、符合 P14 的方案與金鑰配置方式；不在文件或聊天中保存金鑰。
2. 投資與知識庫 Firebase 的實際方案、每日額度與原功能用量。確認後才能分別換算讀取／寫入目標上限；不能只依 AI 訊息數推定資料庫用量。

目前對話的本機保存與 API 供應商的處理／保存是兩件事；P8 不會取消 P14 的要求。

## 九、現有 Gemini 介接核對與新助理方向

官方文件核對日期：2026-10-02。本節是研究結果與介接建議，未修改或測試既有應用程式的 API 呼叫，也未發送付費模型請求。

現有 `src/lib/gemini.ts`：

- 優先模型：`gemini-2.5-flash-lite`。
- 後續嘗試模型：`gemini-3.1-flash-lite`。
- 端點：`v1beta/models/{model}:generateContent`。
- 網路／特定 HTTP 錯誤會自動重試，並可能切到下一個模型。這是既有標籤與筆記關聯功能的行為；不能直接沿用到選擇 P13.A 的新助理。
- 目前是瀏覽器端讀取 `VITE_GEMINI_API_KEY` 並直接呼叫。新助理的三家供應商應透過後端統一連線、權限驗證與用量控制。

核對結果：

1. 模型版本、API 介面與 API 路由版本是不同概念。`v1beta` 不表示只能使用舊模型；官方 SDK 也可使用這個路由版本。[Google API 版本說明](https://ai.google.dev/gemini-api/docs/api-versions)
2. `generateContent` 已屬於較早的介面，但仍完整支援；Google 推薦新專案採用已正式發布的 Interactions API。[Google Interactions API](https://ai.google.dev/gemini-api/docs/interactions-overview)
3. `gemini-2.5-flash-lite` 較舊，但截至核對日期沒有宣布關閉；2.5 系列存取限制仍需依帳戶確認。Google 對新專案列出 `gemini-3.5-flash-lite` 與 `gemini-3.8-flash` 等較新選擇。[Google 模型清單](https://ai.google.dev/gemini-api/docs/models)、[模型停用資訊](https://ai.google.dev/gemini-api/docs/deprecations)

新助理介接建議：

| 供應商 | 建議介面 | 使用方式 |
| --- | --- | --- |
| Google Gemini | Interactions API | 預設供應商；以客戶端維護目前對話，停用可選的 API 對話物件保存，仍遵守供應商必要保存政策。 |
| OpenAI GPT | Responses API | 手動切換；沿用目前對話及使用者偏好，不另建立一份聊天紀錄。[OpenAI 官方文件](https://developers.openai.com/api/docs/guides/migrate-to-responses) |
| Anthropic Claude | Messages API | 手動切換；提交相同的可攜式對話與相關資料，按該介面處理格式差異。[Claude API 文件](https://platform.claude.com/docs/en/api/messages/create) |

模型安排詳見第十節。使用者已要求再加入一個可在同一個付費帳號內切換的 Gemini 模型；依既有的成本偏好，初始選型為 Gemini 3.5 Flash-Lite，不取代 Gemini 3.8 Flash 預設。使用具名的穩定模型，避免無聲更換版本或費率；不自動切換到其他模型。[Gemini 模型與版本](https://ai.google.dev/gemini-api/docs/models)、[Gemini 費率](https://ai.google.dev/gemini-api/docs/pricing)

換用新版模型仍不代表市場資訊即時。題材日期、筆記引用與聯網查證的規則繼續適用；模型更新不取代來源核對。
