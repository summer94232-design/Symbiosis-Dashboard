# 全文搜尋、完整行程時間與批次可靠性（2026-09-09）

本次延續既有修正，顯示版本仍為同日的 `v26.9.9`。未部署、未連接正式 Google／Firebase 寫入，也未改動使用者備份。本文取代先前紀錄中的「不搜尋正文」與「略過有時間／跨日／重複事件」限制。

## 已完成

- KMS 搜尋涵蓋標題、標籤、網址、正文純文字與富文字節點。相容正文仍在 notes 的舊資料，搜尋跨所有筆記，命中後才分頁；既有標籤篩選仍可搭配。全文資料僅在記憶體依帳號快取 90 秒，修改後失效，不額外放進 localStorage。讀取失敗明確顯示錯誤。
- Google pull 保留 start／end、時區、recurringEventId、originalStartTime 及版本；不再因事件有時間、跨日或重複而略過。月曆採台北時間，每個涵蓋日期皆顯示事件；全天的結束日期輸入包含當天，API 使用不含終點的結束日期。
- 本機可新增／編輯有時間及跨日行程。Google 重複系列展開成每次發生的事件，編輯／刪除只作用於本次；整組 RRULE 重複規則仍在 Google 管理。只改標題時保留原始時間、秒數及時區，不把時間壓成全天。
- 重複系列繼承的 sourceId 不再誤綁多個發生次數。Google 將既有單次事件改成系列時，以發生次數取代本機舊父項，不刪除 Google 系列。原生事件連結中斷可於後续同步補回。
- Google PATCH／DELETE 使用 ETag 條件；本機 pull 寫回以交易比對完整基準資料。push 回覆期間若本機有新編輯，保留新內容並記錄下次仍需推送。新增 Google 事件採穩定 ID，查詢與新增同時發生或回覆遺失時可去重。Google 與 Firestore 仍不是跨服務原子交易，失敗會列報並供重試。
- KMS 標籤改名：筆記標籤、索引及排序同一交易提交，使用交易讀到的新標籤避免蓋掉同時新增的其他標籤。排序另有版本比對。改名後畫面直接依摘要重新整理，避免統計觸發器延遲顯示舊標籤。
- 產業股票與新增上下游關係共同交易提交；舊編輯不得蓋掉較新資料，重試不新增重複關係。產業關係操作加上失敗訊息與鎖定解除，表單寫入期間禁止再編輯。
- 法說會／Yahoo 匯入逐批以交易讀取並合併最新個人資料；以帳號共用請求、固定原 session，已完成批次可安全重試。失敗顯示已確認完成數。xlsx 在讀檔前固定帳號、讀檔失敗解除忙碌、保留真正的批次錯誤訊息。
- 行程寫入加入防重入鎖、固定新增 ID、交易與失敗保留表單；回覆遺失後重試同一內容不再新增第二筆。

## 明確範圍與後續

- Google 沿用原同步窗口：pull 為前後半年，本機尚未連結的新行程推送未來半年；超出窗口未出現不視為刪除。取消事件依 Google 回傳及既有連結辨識，並非下載所有歷史及無限未來重複次數。
- 全文首次搜尋會讀取所有有效摘要及正文，採 20 筆併發分組。筆記量大時仍有讀取費用與等待時間；跨裝置變更最多可能受 90 秒記憶體快取影響。PDF／圖片附件 OCR 或附件二進位內容本次未納入。
- 標籤單次原子改名最多 449 則筆記；超量在寫入前停止。產業儲存最多新增 449 條關係。法說會每批 400 組，整份匯入可能分批完成，不宣稱全部批次一起回滾。
- 標籤交易涵蓋查詢時選出的筆記；其他裝置在查詢後新增的筆記不在此次集合內，可再改名一次處理。不宣稱 client transaction 能鎖住全帳號集合。
- TWR 保留現有相鄰快照與區間淨流量算法，畫面、圖例統一標示「近似 TWR」。建議先維持此方案；若未來要精確 TWR，須從資料完整的基準日起記錄每次外部現金流前後估值，再切段連乘。缺少估值的歷史不回填假資料，也不重寫快照。
- 已記錄只使用元大單一券商，不再把多券商支援列為必要工作。
- F16／F17 及使用者暫緩的實際歷史帳務核對，維持暫緩。遠端 CI 與正式部署尚未執行。
