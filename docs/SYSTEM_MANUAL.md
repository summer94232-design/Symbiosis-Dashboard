# Symbiosis 個人系統介紹手冊

## 1. 系統定位

Symbiosis 是一個單頁式個人管理系統，分為三個彼此串接的領域：

1. 投資：交易、持倉、現金、股利、績效、融資、觀點與研究資料。
2. 知識：筆記、附件、標籤、AI 輔助、雙向連結與知識圖譜。
3. 行事曆：財經事件、法說會、任務、每日重點與 Google Calendar 同步。

前端使用 React 19、TypeScript、Vite；主要資料存於兩個 Firebase 專案：investDB 儲存投資與行事曆資料，kmsDB 儲存知識庫資料與附件。Netlify Functions 代理 Google Calendar、新聞、Yahoo、MOPS、市值與海外報價等服務。

## 2. 登入與帳號

- 登入時會同時登入 investment 與 knowledge 兩個 Firebase Auth。
- 兩邊 email 必須相同；任一登入失敗時會登出兩邊。
- 畫面等待兩邊 Auth 初始化完成後才顯示系統。
- 目前多帳號切換會把帳號密碼可逆地存於瀏覽器，此功能有重大安全風險，正式使用前應依稽核報告更換。
- 所有用戶子集合的路徑形式為 `users/{investAuth.uid}/{collection}`。

## 3. 核心資料與關聯

### investDB 用戶資料

| Collection／文件 | 用途 | 主要關聯 |
|---|---|---|
| `trades` | 買賣、費稅、融資資訊、收付總額 | 持倉、現金、損益、年度復盤、KMS 交易日誌 |
| `cashflow` | 入金與出金 | 可用現金、XIRR、資產趨勢 |
| `dividends` | 現金股利與股票股利 | 現金、持股攤薄、行事曆、年度復盤 |
| `assetSnapshots` | 每日總資產、市值、現金、融資負債 | 資產趨勢、CAGR／XIRR |
| `watchlist` | 自選股與技術欄位 | 選股追蹤 |
| `sentiments` | 當下觀點、目標價、信心與事後結果 | 觀點追蹤 |
| `industryMap` | 公司與產業分類 | 產業地圖 |
| `industryRelations` | 公司間供應／客戶／合作關係 | 產業脈絡圖 |
| `calendarEvents` | 個人及可同步事件 | 月曆、Dashboard、Daily Brief、Google Calendar |
| `calendarWatchList` | 額外關注法說會的股票 | 月曆、Google Calendar |
| `investorMeetingOverrides` | 個人新增或隱藏的法說會日期 | 與共用法說會合併後顯示及同步 |
| `tasks`、`taskProjects` | 任務、專案與排序 | 任務頁、月曆、Dashboard、Daily Brief |
| `stockDict`、`stockDictFull` | 代號與名稱字典 | 表單自動完成與顯示 |
| `settings/*` | 現價、群組、個人資料、快照、Google token 等 | 全系統設定 |

### investDB 全域資料

- `investorMeetings/{code-yearMonth}`：法說會共用基礎資料，包含股票代號、名稱、月份及日期陣列；登入用戶只能讀取，只有受信任的後端工作可寫入。
- 使用者從 Yahoo、xlsx 或手動新增／刪除日期時，只更新自己的 `investorMeetingOverrides`。讀取時以「共用日期＋個人新增日期－個人隱藏日期」產生最後結果，不影響其他帳號。

### kmsDB 用戶資料

- `notes`：標題、內容、類型、URL、附件 URL、圖片 URL、hashtags、links、建立／更新時間。
- `trash`：刪除後的筆記與 `deletedAt`。
- `settings/tagOrder`：父標籤與子標籤排序。
- Storage：圖片與文件附件；目前實際檔案不包含在 JSON 備份中。

## 4. 投資系統

### 4.1 儀表板

儀表板平行讀取交易、股利、出入金、最後現價、股票群組及賣出追蹤設定。主要輸出：

- 持股市值、成本、未實現損益、報酬率與配置占比。
- 可用現金、已實現損益、總資產概況。
- 融資部位與整戶維持率、加碼試算。
- 即將到來的 14 天行程、未完成任務。
- 近期賣出後上漲警示與機會損益。
- 手動更新 Fugle 現價；成功後寫入 `settings/lastPrices`，不受背景時段限制，並等待今日資產快照完成後顯示成功、關閉、缺價或失敗原因。

現價缺失時畫面會以成本代替市值，該檔未實現損益顯示為 0；使用時需留意這是估值 fallback，不是市場價格。

### 4.2 買賣紀錄

- 支援新增、編輯、刪除與 CSV 匯入。
- 台股股票與 ETF 自動計算手續費、交易稅與收付金額。
- 股票代號與名稱支援雙向自動完成：輸入代號會帶入名稱，輸入名稱前綴會反查代號；多筆符合時顯示候選清單。
- 支援整股、零股、現股、融資買入與融資賣出。
- 融資賣出需輸入償還金額（本金＋利息）；CSV 無法得知時需事後補登。
- 代號與名稱會同步到股票字典。
- 系統按交易日期與同日穩定順序計算當下可用股數；超賣會顯示錯誤並禁止儲存，CSV 匯入也會拒絕超賣列。

### 4.3 持倉

持倉由全部交易與股票股利按日期重播計算：

- 買入：新成本 = 舊成本 + 價格 × 股數 + 手續費；均價 = 新成本 ÷ 新股數。
- 股票股利：增加股數、總成本不變、均價攤薄。
- 賣出：已實現損益 = 賣出淨收入 − 當時均價 × 賣出股數。
- 現股報酬率分母為總成本；融資部位報酬率分母為自備款。
- 可更新現價並檢視市值、損益與配置。

### 4.4 出入金與股利

- 出入金記錄入金、出金、日期與備註。
- 股利記錄現金股利與股票股利；現金股利計入可用現金，股票股利依日期加入持股時間軸。
- 可用現金公式：`入金 − 出金 − 買入收付 + 賣出收付 + 現金股利`。
- 融資賣出的 `total` 已扣償還款，現金計算不會再扣一次借款。

### 4.5 資產趨勢

- 讀取 `assetSnapshots` 繪製總資產趨勢。
- 自動背景補寫依裝置本地時間於 08:00–22:00 執行；使用者手動按「更新現價」則全天皆可更新本地日期的當日快照。
- 每個本地日期固定一筆快照；同日再次更新現價會更新當日快照，不會新增多筆或刪除其他日期資料。
- 可手動保存／刪除快照、切換前端自動快照。
- 快照內容：持股市值、可用現金、融資負債、總資產。
- 總資產公式：`市場價值 + 可用現金 − 融資借款`。
- 可對照台灣加權指數、處理出入金對績效曲線的影響。
- 自動快照僅在 08:00–22:00、今日現價有效、所有持股都有價格時執行；依賴使用者開啟系統，不是後端排程。

### 4.6 歷史損益與年度復盤

- 歷史損益由交易時間軸產生每筆賣出的成本基礎、已實現損益與報酬率。
- 年度復盤提供月份／年度損益、股利、含息報酬、勝率、交易筆數、平均持有天數、MDD、熱力圖與交易明細。
- 資產快照分頁以 XIRR 計算年化報酬，將入金視為負流、出金視為正流，以排除增資時點影響。
- 自訂區間可重新計算 XIRR、MDD、勝率與平均持有天數。
- XIRR 必須同時存在正、負方向現金流且資料足夠；否則顯示無法計算。

### 4.7 融資管理

- 融資借款：`floor(股票價值 × 融資成數 ÷ 1000) × 1000`。
- 整戶維持率：`融資股票目前市值 ÷ 融資借款 × 100%`。
- 追繳參考線 130%，斷頭參考線 120%，安全參考線 160%。
- 可一次加入多筆加碼試算，逐筆累計新市值、新借款、自備款與維持率。
- 壓力測試可計算全體下跌 10／15／20% 或自訂跌幅後的維持率，也可估算單一股票下跌到整戶追繳線的幅度。

### 4.8 自選股、觀點與賣出追蹤

- 自選股支援台股、日股、美股，保存研究欄位並顯示現價、均線與技術指標。
- 觀點追蹤保存多空／中性判斷、理由、信心、目標價與事後評估，並可更新現價。
- 賣出追蹤按 7、14、30、90、180、365 天或全部期間，計算賣後漲跌、賣對／賣早、準確率及機會損益。
- Dashboard 的賣早通知與賣出追蹤共用 `settings/soldAlert`。

### 4.9 產業地圖與產業脈絡

- 產業地圖管理公司代號、名稱、產業／子產業、供應鏈位置及備註。
- 產業脈絡以公司為節點，建立供應、客戶、合作等有向關係，支援聚焦單一公司查看上下游。

### 4.10 設定、匯入與備份

- 支援交易、出入金、股利的 CSV 匯入與 Excel 匯出。
- 支援完整 JSON 災難復原備份：保留原始欄位及文件 ID。
- 還原採 upsert；備份不存在的線上文件不會被刪除，因此不是鏡像還原。
- 還原每 400 筆一批；跨批次不具整體交易性，中斷後可重跑。
- 完整備份涵蓋多數 invest collections（包括個人法說會 override）與 KMS notes／trash，但不含 KMS Storage 實體附件，也不含唯讀的全域 `investorMeetings`。

## 5. 知識系統

### 5.1 知識庫首頁

- 筆記類型：文字、網址、圖片、文件。
- 知識庫首頁以 Firestore cursor 分頁，每次讀取 40 則 `notes` 摘要；按「載入下一頁」才讀下一批。首頁搜尋與標籤數量以目前已載入的分頁為範圍。
- `notes/{noteId}` 只保存標題、標籤、類型、連結、時間及縮圖 URL 等摘要；完整 `content`、`contentDoc` 與圖片資產清單存於 `noteBodies/{noteId}`，只有展開或編輯時才讀取。
- 摘要另保存最多 300 個標題／標籤搜尋片段及父子標籤路徑，首頁可直接查詢尚未載入分頁的筆記；`metadata/tagStats` 保存全域標籤與未分類數量。
- 知識圖譜只讀摘要與 links；匯出頁先讀摘要，按下匯出後才每批讀取 20 篇正文並顯示進度。
- 筆記卡片使用 IntersectionObserver 虛擬化，僅建立視窗附近（含 700px 預載區）的卡片內容；離開範圍後保留等高占位，降低大量卡片的 DOM 與圖片請求。
- 支援標題／內容／標籤搜尋、建立／更新／標題排序、標籤篩選。
- 模板：交易日誌、選股分析、法說會筆記。
- 交易日誌模板會拉取大盤指數與當日交易，組成市場快照與操作計畫。
- 文章內容使用富文字編輯器，可在游標位置插入、貼上或拖入多張圖片；舊版純文字筆記可直接開啟與繼續編輯。
- 手機照片會先在瀏覽器端轉檔與壓縮：正文圖最長邊 2048px、目標 1.5MB，另產生最長邊 480px 的縮圖；HEIC／HEIF 解碼器只在遇到該格式時動態載入。
- 新圖片存於 KMS Storage 的 `users/{kmsUid}/notes/{noteId}/images` 與 `thumbnails`；列表採瀏覽器 lazy loading 並只使用縮圖，展開文章或編輯時才載入正文圖。
- 圖片上傳草稿記錄在本機瀏覽器；未儲存且超過 24 小時的圖片會在下次開啟知識庫時核對 notes／trash 後清除，不會為了清理而下載圖片內容。
- 圖片草稿亦會以 best-effort 寫入 `imageUploadDrafts`；部署 `firebase-functions/` 後，每週一 03:00 由後端核對 notes／noteBodies／trash，清理跨瀏覽器或跨裝置留下的孤兒圖片。排程 Functions 不部署就不會產生費用。
- `.docx` 上傳會用 Mammoth 抽取文字；新文件存於 `users/{kmsUid}/notes/{noteId}/files`，單檔上限 50MB。
- 舊資料不會自動批次下載；首頁只檢查目前 40 則分頁並顯示待遷移數量。按「遷移舊附件」後才逐筆拆分摘要／正文、搬移舊原圖並產生縮圖。載入下一頁後可繼續下一批；失敗時保留舊資料，可再次執行。
- AI 可依標題／內容產生標籤，或從其他筆記中建議相關連結。
- links 以筆記 ID 儲存；新增、修改、刪除筆記時，筆記本體與所有反向連結會在同一批次寫入，整批成功或整批失敗。
- 批次匯入支援 JSON／CSV。

### 5.2 標籤管理

- `/` 表示階層，例如 `投資/台股`。
- 可拖曳父／子標籤排序，結果保存於 `settings/tagOrder`。
- 更名父標籤時會連帶更名所有子標籤。
- 程式內有標籤合併邏輯，但目前 lint 指出該 handler 未被使用，UI 是否可達需再確認。

### 5.3 知識圖譜

- 以標籤與筆記建立互動圖譜。
- 可搜尋標籤、展開／收合節點、查看筆記之間的連線與標籤群組。
- 圖譜資料目前每次進頁都會讀取全部筆記。

### 5.4 垃圾桶

- 刪除筆記時把原文件移到 `trash/{原ID}`，保留 ID 以免關聯指向失效。
- 刪除與復原都使用原子批次，不會留下 notes 與 trash 只有一側完成的狀態。
- 可復原、永久刪除或清空垃圾桶。
- 超過 30 天的資料只會在使用者開啟垃圾桶頁時清理，不是背景排程。
- 附件實體檔不會跟著刪除。

### 5.5 資料健康中心

- 位於「帳戶管理」，可檢查 KMS 斷鏈、單向連結、自我連結、notes／trash 重複、過期垃圾及無效日期。
- 自動修復只處理可明確判定的異常：移除不存在或自我連結、補齊反向連結、以有效筆記為準清除重複垃圾、清除日期有效且超過 30 天的垃圾。
- 無效垃圾日期不會自動刪除，會保留供人工確認。修復採分批原子寫入，完成後重新掃描。

### 5.5 NotebookLM 匯出

- 可匯出全部或依標籤篩選的筆記。
- 格式包括單一 TXT、依標籤拆分 TXT、Markdown。
- 產物適合手動上傳 NotebookLM；系統本身不直接把資料送到 NotebookLM。

## 6. 行事曆與任務

### 6.1 財經月曆

事件來源包括：

- 硬編碼的 FOMC 日期。
- 每月第三個星期三的台指期結算日。
- `investorMeetings` 法說會。
- 用戶的 `calendarEvents`。
- `dividends` 除權息。
- 未完成且有截止日的 tasks。

可依事件類型篩選、只顯示持股與關注清單、切換月份、新增／編輯／刪除事件、手動匯入法說會 xlsx、從 Yahoo 更新全市場法說會。

### 6.2 法說會關注清單

- 額外指定要關注的股票；持股會自動加入「我的股票」篩選。
- 股票名稱由 `stockDict` 帶入。
- 同頁管理 Google Calendar 連結及要同步的事件種類。

### 6.3 任務管理

- 任務欄位：標題、完成狀態、優先級、截止日、標籤、專案、備註、排序。
- 專案有名稱、顏色與排序。
- 支援按專案／標籤／完成狀態篩選與拖曳排序。
- 篩選狀態拖曳只調整可見任務，隱藏任務保持相對位置；系統會重建完整且唯一的 order。
- 刪除專案時同批刪除該專案內任務。
- 有截止日且未完成的任務會進月曆；未完成任務也會出現在 Dashboard 與 Daily Brief。

### 6.4 每日重點

- 彙整當日行程、任務與多來源財經新聞。
- 新聞由 Netlify function 並行抓 NewsAPI、鉅亨與 Yahoo RSS，再按 URL 去重。
- 新聞結果存於 `sessionStorage`，同一分頁 session 可減少重抓。

### 6.5 Google Calendar 同步

- 使用 OAuth 取得 Calendar 權限，建立／重用「Symbiosis 財經行事曆」。
- 同步範圍為今日起未來六個月，前端每批送 25 筆。
- A 類手動事件支援雙向比對：Google 端新增、修改、刪除可回寫 Firestore；Firestore 變動可新增／更新／刪除 Google 事件。
- B 類計算事件（法說會、除權息、FOMC、期貨結算）以單向補缺為主，不持續同步更新／刪除。
- 以 `sourceId` extended property 與 `googleEventId` 維持對應，降低重複建立。
- 同步是手動觸發；部分成功時可能已在兩端留下部分更新，應查看錯誤摘要。

## 8. 資料讀取與快取行為

- `trades`、`dividends`、`cashflow`、`assetSnapshots`：同一 UID、同一分頁記憶體內快取 90 秒；需要倒序時在前端反轉副本。
- 共用層保存進行中的 Promise；多個元件同時要求同一 query 時只會發出一次 Firestore 查詢。載入期間若資料已被寫入／失效，舊結果不會重新寫回快取。
- KMS Sidebar、首頁、關聯圖、標籤、匯出及垃圾桶共用 notes、tag order、trash 資料層，切換子頁時不重複全表讀取。
- Dashboard、行事曆、每日簡報與任務管理共用 calendar events、tasks、task projects；股票代號／名稱查詢也會合併同時請求並快取搜尋結果。
- 寫入、刪除、匯入或備份還原後會清除相關快取；切換帳號與登出會清除所有資料與 pending request。
- 現價：全域 PriceContext，並保存於 `settings/lastPrices`；頁面可先使用 Firebase 快取，再手動更新外部報價。
- 市值股數：MarketCapContext 在前端 session 共用。
- 新聞：`sessionStorage`。
- 下一階段重點是把日期／完成狀態篩選下推到 Firestore，並為大量資料加入 cursor 分頁。

## 9. 資料健康中心

- 位置：帳戶管理 → 設定與備份 → 資料健康中心。
- 進入頁面會自動檢查；「重新掃描」會先讓共用快取失效，再讀取最新資料。
- 嚴重：交易欄位錯誤、依時間軸計算的超賣、出入金格式錯誤、筆記與垃圾桶 ID 衝突。
- 警告：融資賣出缺償還金額、疑似重複交易、股利／快照格式錯誤、KMS 失效連結。
- 提醒：KMS 連結未雙向同步、自我連結、垃圾桶資料超過 30 天或日期無效。
- 顯示每類問題筆數與最多五筆範例；可安全修復的 KMS 問題會顯示修復按鈕，交易與格式問題仍只診斷、不自動改寫。

## 10. 部署與營運注意事項

- 本地若需 Netlify Functions，應用 `netlify dev`，單純 `npm run dev` 無法提供 proxy。
- 必須設定兩組 Firebase 前端設定、Google OAuth client、Netlify 後端 secrets，以及外部市場／AI 金鑰。
- 不要把 `.env` 提交；目前 `.gitignore` 已忽略 `.env`。
- investDB 提供 `firestore.invest.rules` 與 `firebase.invest.json`；KMS 提供 `firestore.kms.rules`、`storage.kms.rules`、`firebase.kms.json` 與 Emulator 規則測試。KMS 因跨 Firebase 專案 UID 可能不同，部署前必須依 `docs/KMS_MIGRATION.md` 建立唯讀 UID mapping 並完成遷移驗證。
- investDB 規則部署範例：`firebase deploy --only firestore:rules --config firebase.invest.json --project <invest-project-id>`。
- KMS 規則部署範例：`firebase deploy --only firestore:rules,storage --config firebase.kms.json --project <kms-project-id>`。
- 全域搜尋／標籤 metadata 初次建立：先執行 `npm run kms:metadata:dry-run -- --project=<kms-project-id>`，確認後再執行 `npm run kms:metadata -- --project=<kms-project-id>`。
- `firebase-functions/` 包含標籤統計／搜尋索引維護及每週孤兒圖片清理；部署前需確認 KMS 專案計費方案與預算警示，再使用 `firebase deploy --only functions --config firebase.kms.json --project <kms-project-id>`。未部署時前端仍可使用，但舊筆記的全域搜尋依賴 metadata 重建，跨裝置孤兒清理不會執行。
- 上線順序建議先部署 `storage.kms.rules`，再部署新版前端並執行舊附件遷移；此規則讓舊全域路徑唯讀，新上傳只能寫入使用者自己的路徑。確認所有舊附件均已遷移、舊物件已由管理端清理後，可將舊路徑的 `read` 也關閉。
- 每次部署至少執行 build、lint、核心計算測試、Firebase rules emulator 測試與備份還原演練。
- `npm test` 目前包含 48 項測試，其中 32 項為現股／融資、整股／零股、ETF／股票、部分賣出／全數平倉、同年度／跨年度的完整財務計算矩陣。

## 11. iPhone 網頁版操作

- iPhone Safari 與加入主畫面的網頁 App 共用同一套功能與資料，手機版只調整畫面配置，不改變計算、儲存或同步邏輯。
- 頂部標題會顯示目前頁面；底部快速導覽依投資、知識庫或行事曆顯示常用入口。「全部」可開啟原本的完整側邊選單。
- 畫面會避開瀏海、動態島與底部 Home Indicator，並依 Safari 網址列及螢幕鍵盤動態調整高度。
- 手機版輸入框及主要按鈕擴大觸控範圍；輸入時不會因字體過小觸發 Safari 自動放大。
- 寬表格可左右滑動；交易紀錄沿用手機卡片顯示。持倉與儀表板摘要在窄螢幕改為兩欄。
- 月曆選取日期後，事件內容改到月曆下方；任務的專案與標籤改為橫向滑動，避免把任務列表推到很下方。
- 表單彈窗在手機上由畫面底部展開，可在鍵盤開啟時獨立捲動；橫向使用時也不再由 PWA manifest 強制鎖定直向。
- 第二輪手機優化：月曆格以事件色點降低擁擠，低頻匯入／同步功能集中在「更多操作」；點日期仍可查看完整事件。
- 儀表板 KPI 卡片縮短並讓每組最後一張單數卡橫跨兩欄，避免右側留下空白。
- 持倉在手機改為摘要卡片；點擊可展開股數、均價、現價、成本、市值、損益與族群編輯。桌面版仍使用完整表格。
- 新增／編輯交易、筆記與任務時，「取消／儲存」列固定在底部導覽或鍵盤上方，所有原欄位與驗證規則維持不變。
- 第三輪介面精修：儀表板的「目前持倉」在手機改成可展開摘要卡，桌面仍保留完整表格與原排序功能。
- 儀表板、股票持倉及買賣紀錄的頁首、主要／次要按鈕、字級與 44px 觸控高度已統一；更新現價與重新載入會顯示成功、部分成功或失敗提示。
- 交易新增、更新、刪除與持倉族群儲存會顯示結果提示；失敗時保留表單內容或原族群設定，避免使用者誤以為資料已寫入。
- 知識庫的搜尋／排序列會固定於內容上方，顯示目前結果筆數並可一鍵清除搜尋；標籤入口及筆記編輯／刪除支援鍵盤與輔助操作。
- 手機行事曆的事件類型篩選改為橫向滑動；日期格、月份切換及事件圖示按鈕具備完整操作名稱與較大的觸控範圍。
- Word 與 Excel 解析工具只在實際匯入檔案時載入，降低第一次開啟知識庫與行事曆的下載量。

## 12. 桌面網頁版操作

- 買賣紀錄的桌面表格每頁顯示 50 筆；搜尋後會回到第一頁，頁尾顯示目前筆數範圍與總頁數。手機卡片仍顯示完整搜尋結果。
- 頁首操作與搜尋列在桌面捲動時固定於上方；交易表格在獨立捲動區內固定表頭。
- 表格維持原始欄位順序：「日期、類型、代號、名稱、價格、股數、手續費、交易稅、收付金額、備註」，並依交易時間顯示最新紀錄在前，不提供額外欄位排序或密度切換。
- 儀表板提供「資金與風險、資產分布、目前持倉、行程任務」快速跳轉；各區塊固定展開，直接顯示完整資訊。
