# 報價、賣出追蹤與每日簡報 — v26.9.18.1

## 已完成的本機修改

- 報價：原先的五個 worker 只限制同時連線，沒有控制每分鐘請求數；300ms 後重試也無法解決分鐘限流。改成所有批次及單筆報價共用 55 次／61 秒的滑動窗口，同代號進行中的查詢共用請求。429 依 Retry-After 等待，未提供時等待完整窗口，最多重試一次。連線設 10 秒逾時；401/403/404 等永久錯誤不重試。
- 補讀 Fugle `lastTrade.price`，保留成交價／參考價的區別。失敗報價仍不視為有效現價；不改動收盤快照、手動 exact TWR 或歷史績效的安全判斷。
- 儀錶板與賣出追蹤呈現缺價代號和錯誤原因。自動快照的例外不再讓已成功寫入的報價回傳空結果。
- 賣出追蹤：原本每次 settings 同步都重新載入交易並將所有 currentPrice 設為 null。改成交易資料與全域報價分開，畫面直接由 PriceContext 計算現價，同步／重新進入頁面不再清空價格。依本批後續澄清，所有更新入口都更新全系統清單，不受目前顯示期間限制。失敗報價不再沿用上一次價格冒充更新成功。
- 每日簡報：保留上次成功取得的新聞，即使重新整理失敗仍可閱讀；sessionStorage 寫入失敗不再遮住成功取得的內容；空新聞快取不會阻止重新載入。
- 後端驗證失敗現在回傳安全的 SDK 錯誤碼，區分權限、服務憑證和一般暫時故障。日誌不包含原始錯誤、token、金鑰或 UID；仍執行撤銷檢查、白名單和用量檢查。

## 全系統共用現價（同批需求澄清）

- 任一「更新現價」入口都收集完整的交易代號（包含歷年已賣出）、watchlist、sentiments、industryMap 與加權指數 IX0001。尚未進入過的頁面也會涵蓋；目前頁面可補入尚未儲存的試算代號。
- 代號清單本身也以帳號分隔快取 90 秒；交易、選股、觀點或產業地圖異動的同步通知會使清單快取失效，不因單純寫入報價而重讀。
- 代號去重：台股保留原有代號；日、美股使用 JP:/US: 前綴避免同碼碰撞。外股也寫入同一份 `settings/lastPrices`，不再僅保留於選股追蹤的元件 state。外股來源未提供交易日時不偽造收盤日期。
- 所有同時更新共用一個流程，只查一次、寫入一次；更新途中新加入的代號另行補查，不重查已處理代號。成功報價在本次批次完成後保留 60 秒的重複點擊保護；只補查失敗／新增代號。重用報價不延長有效期限，不更改原始取得時間。
- 切換頁面只讀共用 state／Firestore 報價，沒有自動觸發新的報價查詢。選股追蹤、觀點追蹤、賣出追蹤、儀錶板、持倉與融資維持率直接使用共用現價；儀錶板賣出提醒也即時計算。組合試算與年度回顧沿用同步通知讀取，年度回顧額外採用共用價格且排除失敗報價。
- 新增觀點與 KMS 交易日誌也優先使用共用報價；已有資料不再自行重抓。歷史 K 線、MA 與股數屬不同資料，仍由其專用操作更新。
- 一次全系統更新若超過分鐘配額，會排隊等待，頂部會顯示共用更新狀態。版本維持 v26.9.18.1，屬於同一批尚未部署的修改。

## 新聞問題的實際診斷與限制

使用者回報「驗證服務暫時無法使用」，對應 `authorizeApi` 的 Firebase `verifyIdToken(token, true)` 基礎設施錯誤分支。這發生於新聞來源請求之前。

唯讀確認：

- Fugle 單檔查詢 HTTP 200、鉅亨網 HTTP 200、Yahoo RSS HTTP 200 且含 50 個 item。
- Netlify production 有三個必要 API 設定；服務帳號金鑰未停用，且仍有自訂角色綁定。
- 線上 API 對格式正確但簽章錯誤的測試 JWT 回傳 401，公開簽章驗證路徑可以正常拒絕無效憑證。
- 既有專用角色含 Firebase 帳號讀取及 Firestore 配額所需的既有六項權限。尚未取得真實登入請求的底層錯誤碼，不能認定根因一定是 IAM 或私鑰。
- Netlify 的服務帳號機密無法由唯讀 API 還原；管理登入沒有 impersonation 權限，沒有為此新增權限。Cloud Logging 查詢未取得對應錯誤。

**第三項尚未證實修復。** 本批新增診斷後，需部署並以既有登入狀態重新整理新聞，依回傳碼確認後端故障原因。若需正式設定變更，再提出明確變更內容供批准；不可移除驗證、停用撤銷檢查或直接擴大 IAM 權限來繞過錯誤。
