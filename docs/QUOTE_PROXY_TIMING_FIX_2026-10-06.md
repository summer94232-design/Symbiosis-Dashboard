# 正式報價代理逾時修正 — v26.10.6.1

後續使用者要求取消收盤確認，已與本批修正合併為本機 `v26.10.6.2`，見 [每日快照趨勢模式](DAILY_SNAPSHOT_TREND_2026-10-06.md)。以下保留本批當時的報價診斷與驗證紀錄。

本批處理發布後十檔持股缺價、估值完整度為 0，以及快照提示同時聲稱「現價已更新」的問題。已依使用者本次部署授權隨 `v26.10.6.2` 上線，新帳號正式驗收十檔報價全部成功；詳見 [正式發布紀錄](RELEASE_2026-10-06_v26.10.6.2.md)。以下驗證章節保留部署前的診斷結果。

## 已確認原因

Fugle 改由登入保護的後端代理取得報價後，前端仍沿用單次 5 秒、整批 8 秒的舊期限。代理請求除了讀取行情，還經過登入驗證與共用額度交易；多檔報價分組排隊，後面的股票會共用已快耗盡的期限。單檔成功驗收沒有覆蓋這個多檔情境。

使用原核准帳號與相同正式代理，執行實際編譯的前端報價函式，比較使用者提出的十檔公開代號。沒有讀取私人持倉、保存現價或建立快照。

| 流程 | 結果 |
|---|---|
| 舊版 | 約 8.0 秒結束，4／10 成功，11 次 HTTP 嘗試；部分在 5 秒被前端中斷，6757 沒有開始請求 |
| 修正版 | 約 11.8 秒完成，10／10 成功，10 次 HTTP 請求，沒有中斷或重複呼叫；全部來源日期 2026-10-06 |

修正版有一檔代理回應需要約 11.8 秒，同一 API 金鑰仍能成功。因此已確認短期限是可重現的問題，沒有證據需要更換金鑰或刪除股票紀錄。測量沒有拆分冷啟動、驗證、資料庫交易及上游各自耗時，不將其中某一階段猜測為唯一原因。

## 修改

- 單次代理請求最多 20 秒，整批最多 60 秒，讓分組排隊與混合行情的補查仍有時間完成。仍維持最多五個同時請求，不放寬每分鐘／跨裝置額度。
- 行情歷史也採 20 秒代理等待；原有排隊與受限重試維持。
- 前端中斷或網路結果未知時，不立即自動重送該檔現價，避免原代理仍在執行時重複付費／消耗額度。明確的伺服器失敗仍保留最多一次、受整批期限約束的重試；429 仍立即顯示限流並保留冷卻。
- 共用額度時間戳改在交易讀取／重試後取得，避免長等待使預約時間過早；仍是每 70 秒最多 55 次上游預約。
- 缺價提示改為「某些持股缺少有效現價，快照未儲存」，停用快照提示亦移除不一定成立的「現價已更新」。價格全部失敗時不再同時宣稱已更新。
- 保留價格來源／日期、參考價與成交價區分，以及缺價、舊日期、未確認收盤時停止保存快照的原保護。不用成本偽造現價或保存精確收盤快照。

主要修改：`src/lib/fugle.ts`、`quoteTiming.ts`、`hybridQuotes.ts`、`snapshot.ts`、`netlify/lib/quote-budget.js` 與版本常數。

## 驗證

- 131 項相關測試通過：新增十檔各需六秒的並行／排隊案例、60 秒整批停止且不重複中斷請求、短期限保留成功結果、慢市場快照仍可補查，以及交易重試後的預約時間戳。
- 共用全域更新與帳務／報價代理呼叫端另有 42 項測試通過；與上述測試有重疊的行為範圍，不以筆數相加宣稱不同功能的總數。
- TypeScript、修改檔案 ESLint、正式建置與 build 前置六項 runtime 檢查通過；既有大型 bundle 提示維持。
- 真實診斷使用正式版本後端代理及其既有登入／共用額度，新前端函式在本機執行。新後端時間戳修正已完成模擬交易測試，尚未發布，不能將這次診斷當成完整新版正式部署驗收。
- 診斷只寫入必要登入與額度紀錄，不更新私人帳本、筆記、現價或快照；未執行 AI 生成。

安全的修正前後資料：[舊版結果](../log/quote-recovery-2026-10-06-before.json)、[修正版結果](../log/quote-recovery-2026-10-06-after.json)。只包含公開代號、狀態與時間，不含金鑰、登入 token 或私人持倉金額。

上線後一般更新可能比舊版的八秒等待更久，但會等待實際報價完成，且仍有總時限。若來源限流或網路真正失敗，查看提示後再手動重試；完整度與快照保護仍會如實反映未取得的資料。
