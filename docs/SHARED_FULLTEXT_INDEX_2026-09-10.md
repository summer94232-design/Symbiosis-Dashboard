# 完整全文搜尋與讀取成本（v26.9.10.3）

已移除每 40 筆手動繼續搜尋。新搜尋一次涵蓋全部索引筆記，包括舊格式正文、富文字文字節點、標題、標籤與網址；支援 NFKC、忽略空白與長字串比對，不截斷正文。

## 實作與成本範圍

- Firebase Admin 維護 `kmsSearch/{investUid}/state/manifest` 與 `fulltextShards`。16 個固定雜湊分片；gzip/base64 壓縮，每頁最多 640,000 字元。大分片可分頁，前端自動全部載入，沒有逐批操作。
- 首次搜尋讀取 1 份 manifest 加所有索引頁。1,000 筆短正文的自動測試為 17 次讀取；實際取決於正文壓縮後大小，17 並非所有資料的上限。
- 同一分頁的索引快取有效 60 秒，期間換關鍵字不新增讀取。之後再次搜尋或按更新按鈕會讀 manifest，僅重新下載版本變更的分片。未變分片保留在記憶體，關閉分頁／清除登入快取後重新載入。沒有定時背景掃描，也不把正文持久存到 localStorage。
- 筆記／正文變更觸發器讀取目前文件與所屬分片，以交易更新。刪除筆記時移除搜尋項目，不收錄殘留孤兒正文。相同事件重送不重複寫入，正文單獨變更也會更新。
- 新索引的前端只允許本人或既有 investUid 映射帳號讀取；用戶端不能寫入索引。壓縮資料不是加密，仍受原有帳號與 Firebase 權限保護。
- 建立索引有一次性成本：文件 ID 清單約 N 次、目前摘要與正文約 2N 次，另有計數查詢、每批 manifest／既有索引頁讀取、交易重試與寫入。每批同分片最多 40 筆，使用者無需操作批次。這不是費用硬上限。
- 知識庫首頁原有「載入全部摘要」仍會讀取摘要；本次減少的是全文搜尋的額外讀取。既有標籤統計函式的全量統計成本也未在此批變更。
- 索引屬非同步衍生資料，儲存後可能需稍候更新。UI 顯示索引時間；缺少索引、建立中或載入失敗不會假稱全文搜尋完成，不自動退回逐篇掃描。
- 每次交易的新舊頁數合計限制 12 頁（約 7.7 MB 壓縮資料）；超過時明確失敗，既有交易資料不變。超大型知識庫需再細分雜湊桶，不能宣稱本方案適合無限資料量。

## 正式啟用順序（本次未執行）

先確認 KMS Firebase 專案與投資帳號 UID，使用既有管理員環境；不要把管理員金鑰放進前端。以下參數為佔位符。

1. 部署新增規則、索引欄位豁免及兩支索引函式；必須先讓觸發器運作，再建立索引。

   ```powershell
   firebase deploy --config firebase.kms.json --project <KMS_PROJECT_ID> --only firestore:rules,firestore:indexes,functions:maintainKmsFullTextNotes,functions:maintainKmsFullTextBodies
   ```

2. 預檢只做計數，不讀取正文或寫入索引。預設最多 5,000 筆，超過即停止。

   ```powershell
   node scripts/build-kms-search-index.mjs --project=<KMS_PROJECT_ID> --user=<INVEST_UID>
   ```

3. 確認預檢結果後建立一次索引。失敗會保留 building 狀態與已完成分片，重新執行可續建；一般錯誤會釋放鎖，程序中斷則等待一小時鎖到期。已 ready 時拒絕再次全掃。

   ```powershell
   node scripts/build-kms-search-index.mjs --project=<KMS_PROJECT_ID> --user=<INVEST_UID> --commit
   ```

4. 確認 ready 後發布前端。用已知正文詞搜尋，再修改／新增／刪除隔離測試筆記確認觸發器更新。尚未建立時新版前端的全文搜尋會提示建立索引，摘要命中仍可參考。

索引不列入備份：它是可由筆記重建的衍生資料。還原到新帳號後需執行首次建立；還原到既有帳號由觸發器同步處理。批次還原期間應等待處理完成再驗證全文結果。
