# 資產報酬從可連續計算日期重新起算 — v26.9.13.2

資產趨勢的 ALL 區間遇到缺少快照的出入金日後，原有近似 TWR 會停止延續。新增「從資料完整日期重新起算」按鈕，讓使用者保留原始資料並選擇新的比較期間。

## 行為

- 原本的嚴格報酬計算保留；偵測到中斷時提供重新起算按鈕，顯示可用日期。
- 選擇所選區間內最早的正淨值起點，且其後必須能一路計算到最新快照。多個缺口會選擇最後一個缺口之後的連續區段，至少需要兩筆快照。
- 起算日包含當日出入金，以新的期初淨值使用，不重複扣除當日流量；以後入金仍採實際轉帳日收盤後、出金採日終假設。
- 資產與加權指數同步改用同一天歸零；圖表、同期超額報酬及起點文字使用同一期間。大盤只取該日或之前最近的收盤值；若該值無效或起點無資料，不計算大盤報酬，也不改用未來指數代替。
- 顯示新的起算日、起點前報酬未納入及估算性質，並可按「恢復原區間起點」切回。切換 1M／3M／6M／1Y／ALL 時回到原區間模式。
- 金額圖、原始快照、出入金及精確 TWR 資料不變。沒有資料寫入、補造流量或快照，也沒有自動部署。
- 預覽後依使用者要求，移除「此區間有出入金，預設收盤後入金、日終出金……」整段常駐提醒及其專用判斷；計算方式與重新起算操作保留。屬同一預覽修訂批次，仍為 v26.9.13.2。
- 再依預覽回饋，將按鈕縮為 ALL 右側的「重新起算／恢復起點」，移除獨立說明框與「可從…比較至最新快照…」提醒。完整操作名稱保留在無障礙標籤，滑鼠提示顯示候選日期或無法起算原因，圖表下方顯示實際比較起點。

「資料完整」僅表示現有快照與已登錄出入金符合計算條件，不表示遺失現金流已補齊或舊快照已核實為精確收盤淨值。原有完整虧損 -100% 不會被自動抹去；只有使用者明確重新起算才改變比較期間。

## 驗證

修正後正式資料的本機備份：原 ALL 區間因 1/5 缺少快照，從 1/9 起中斷。新功能可自 2026/1/9 重新起算，111 筆快照連續計算至 9/11；這是該備份的涵蓋期間，不宣稱已取得之後的收盤淨值。

新增七項回歸測試：缺少流量日、開端流量不重複扣除、多個缺口、完整虧損及零淨值後再投入、無有效區間、無效或重複資料，以及實際圖表回呼中資產與大盤同步歸零／不使用未來指數。

驗證：全套 384 項測試通過，移除重複宣告後另重跑相關 33 項測試通過，TypeScript 與正式建置通過、lint 通過。建置有大型 chunk 及插件耗時提示。本批次為 v26.9.13.2，尚未部署；正式站台仍是已發布的 v26.9.13.1。
