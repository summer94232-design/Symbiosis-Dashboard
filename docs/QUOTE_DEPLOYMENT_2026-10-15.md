- Netlify 對持久設定的 Functions-only 範圍回覆 403 scope-policy；官方文件說明自訂範圍需 Pro 以上。較廣的 builds／functions／runtime 標準 secret 方案被自動審核要求另取明確同意，未執行。使用者追問原設定與是否再發，並未給較廣範圍同意，故沿用原後端範圍恢復服務，沒有升級方案或擴大祕密範圍。

- 固定程序已對正式環境實跑唯讀預檢通過，未建立第二次部署；其餘功能程式及已驗證 dist 不變。新增兩個發布防漏回歸，設定／部署 suite 共 6/6 通過，lint 通過。先前相關測試／建置結果繼續適用。
- `check:quote-deployment` 只讀持久站台設定，不含某次部署的覆寫。現在它仍列缺 Fugle 是預期情況，不能據此宣稱正式函式失敗；須看固定發布程序的合併檢查與真實登入後的請求結果。

## 已確認的部署缺漏

- 現價及 AssetTrend 的 `IX0001` 歷史行情都透過 `fugle-proxy`。其程式在缺少伺服器 `FUGLE_API_KEY` 時直接回傳 503，尚未預約 Fugle 額度或呼叫來源；來源端一般伺服器錯誤則轉為 502。
- 唯讀查詢 Netlify production／Functions 設定：沒有 `FUGLE_API_KEY`；三項 `API_*` 設定存在。遠端祕密可能是不可讀的占位值，不能把服務帳號無法在本機重新解析視為正式設定損壞。
- 2026-10-06 發布紀錄明載 20 項單次 Functions 覆寫包含 Fugle 金鑰，並警示下次部署須攜帶。2026-10-15 `.15.2` 的實際發布指令未攜帶 `--env`／`--secret-env`。因此確認發布流程遺漏必要報價設定，不再把冷啟動或交易競爭當成已證實原因。
- 使用既有本機金鑰直接唯讀查公開來源：一檔台股現價 HTTP 200；`IX0001` 2026-10-01 至 2026-10-15 歷史行情 HTTP 200、10 筆。沒有保存現價、快照或帳本，也沒有輸出金鑰。
- 正式報價日誌最近四小時有 69 筆執行時間紀錄，沒有登入驗證錯誤紀錄；舊版對用量／共用額度錯誤沒有記錄原因。這不能證明所有暫時性 503 均為同一原因。
- 部分現價可能由富邦快照取得；它成功不代表 Fugle 後端已恢復。加權指數歷史目前依賴 Fugle。

## 本機修正

- 現價／歷史錯誤顯示固定白名單內的後端原因，不再只有 HTTP 503。任意來源錯誤、憑證、文件路徑不進入錯誤顯示或儲存報價紀錄。
- 缺金鑰、缺安全設定及憑證／權限失效直接回報；暫時性 503 最多三次嘗試，採遞增間隔與抖動，維持現價整批期限、跨裝置額度及未知結果不重送的保護。來源端 5xx 維持最多兩次嘗試。
- 用量及共用額度失敗以固定診斷碼記錄，區分競爭、不可用、逾時及權限問題；不改驗證、撤銷檢查或配額成功路徑。
- `npm run check:quote-deployment` 唯讀檢查正式 Functions 的四項必要設定；缺漏或讀取失敗以非零狀態停止，未寫入任何正式設定。這是發布前檢查，須在實際發布程序執行；不會攔截繞過它的手動 CLI／UI 部署。
- 曾試作共用低並行排程；找到明確缺設定後已撤回，現價五個／歷史四個的原並行上限維持。
