# 更新現價、API 額度與自動除權息

本批版本 `v26.10.1.3`，已併入正式版本 `v26.10.1.4`，見 [發布紀錄](RELEASE_2026-10-01.md)。現價存檔完成就回報，除權息公告、資產快照與法說會在背景完成；不新增排程。沒有修改既有私人帳務。

## 現價與 API 規則

- 富果基本方案日內行情每分鐘 60 次，歷史行情另為每分鐘 60 次；富邦行情快照每分鐘 300 次。以實際帳戶與供應商回應為準。[富果方案](https://developer.fugle.tw/docs/pricing/)、[富邦速率限制](https://www.fbs.com.tw/TradeAPI/docs/market-data/rate-limit/)
- 本系統的新版富果現價請求，先向受保護的 `quote-budget` 取得共用額度。Firestore transaction 合併不同裝置與不同函式執行個體的預約，最多 55 次／70 秒；多留時間涵蓋報價傳送的等待。一次批次申請，沒有額度不發送付費／計量報價；額度服務失敗也不直接繞過。
- 重試同樣需要額度。併發仍為 5，沒有提高官方或系統額度。供應商 429 記住 `Retry-After`／冷卻時間並立即回報，不在前景等一分鐘。歷史下載保留原有排隊與重試，本批新增的跨裝置預約用於日內現價。
- 富邦仍使用上市／上櫃各一次市場快照、既有 10 秒快取與受保護的請求額度，沒有改成逐檔大量呼叫。持股／指數的精確成交價查詢及最多 10 檔缺漏補查保留，共用同一段富果時間預算。
- 報價讀取設定約 8 秒預算，單次富果 HTTP 最長 5 秒。達到額度／期限即回報部分成功或失敗；冷卻後再次更新時優先處理上次失敗代號。外股後續批次失敗保留前面已取得的價格。
- 查持股確認名單只讀交易與股利，不再先讀整份市值／現金快照。報價後的資產快照、法說會與除權息不阻塞結果。保留來源日期、成交／參考價區分、舊回應防覆蓋與切換帳號防護。

8 秒是報價等待的設定，並非整體操作的固定完成保證。帳本讀取、認證、存檔、冷啟動及網路仍會影響耗時；本批沒有正式站實測秒數。部署後兩台裝置都需重新整理載入新版；其他程式及未更新的舊分頁使用同一 API 金鑰，並不受新版預約控制。

## 自動除權息

點選全系統「更新現價」後，在背景讀取官方公告。公告存在共用區；全系統每 24 小時最多嘗試一次 TWSE、一次 TPEX，平常每裝置也是 24 小時讀一次。官方失敗保留上一份及來源更新時間；只讀共用資料的重試另有限額。冷執行個體遇到其他個體尚在更新時，不把中間的空資料快取成一天的完成結果。

- [證交所除權息預告](https://www.twse.com.tw/exchangeReport/TWT48U?response=html)、[櫃買資料來源](https://data.gov.tw/dataset/11634)：解析民國日期、每股現金股利及無償配股率。現金增資認購不當成免費配股。ETF 尚待公告金額維持「待公告」。
- 用目前帳號的帳本在畫面試算，不上傳持股給官方網站。未來事件按目前持股；已到除權息日按前一日持股，之後賣掉股票仍保留資格，除權息當日才買入不具該次資格。[證交所投資問答](https://investoredu.twse.com.tw/pages/TWSE_InvestmentQA.aspx?ID=1)
- 在除權息頁與系統行事曆顯示預告；只快取公開公告，不快取不同帳號的資格股數。既有已登錄事件不再重複顯示預告。預告不改現金、持股、損益或資產快照，也不自動推送 Google。
- 「填入實領」準備表單；確認元大實領金額、現金入帳／股票配發日期後才儲存。官方預告沒有實際入帳日，不把除權息日誤當入帳日。含融資、畸零股與外幣有提示；外幣不直接填成新台幣股利。
- 原本手動股利紀錄保留。來源事件使用固定文件 ID 及原有帳本版本 transaction，跨裝置同時確認或與手動登錄競爭時防止重複；相同內容重試不增加第二筆。

這是自動公告／資格試算，實領仍需確認。首次使用以前已從官方預告表移除、且系統從未取得的歷史事件不保證補齊；公告更新時間會顯示，已保存歷史公告保留約 550 天。

## 免費平台用量

本次於 Netlify 已登入的帳務頁實際查得：Free 團隊每月 300 credits，本期 9/6–10/5 已用 228.1、剩 71.9，10/6 重置。15 次正式部署使用 225 credits；Compute 1.5、Web requests 0.9、Bandwidth 0.7。三個專案共用團隊額度，主要消耗是部署。[Netlify 點數規則](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/)

沒有新增／增加原有排程。原始設定中的 Netlify 年度公告每週、GitHub 法說會每日、Firebase 清理每週維持原狀；此處不能以原始設定代替已部署排程的實際使用量。新功能主要新增按需函式讀取與少量公告流量，仍會消耗點數，不代表完全零費用。

公告每日共用一次，正常使用的增量很小；例如 31 次公告更新、每次 10 秒、配置 1 GB，計算費用約 0.86 credits，另計請求及流量。報價額度每批增加一次函式呼叫；例如每月 600 次、每次 1 秒、1 GB，約 1.67 compute credits。這是公式示例，不是已量測函式記憶體／耗時；實際值以 Netlify 帳務為準。目前餘額可容納一般使用，其他專案流量及後續部署仍可能用完 Free 額度，不能保證整個帳戶永遠不超額。
